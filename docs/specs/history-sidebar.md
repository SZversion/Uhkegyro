# 브랜드 홈 버튼과 검색 기록 사이드바

## Why
- 검색 결과를 떠나 별도 기록 화면을 열지 않고 이전 요청을 다시 확인하고 싶다.
- GPT 앱의 상시 기록 목록 구조를 참고하되 기존 브랜드 색상과 개별 검색 요청 데이터를 유지한다.

## Goal
- 좌측 상단 브랜드 아이콘·이름을 즉시 홈 버튼으로 사용한다.
- 데스크톱 왼쪽에 약 200px 기록 사이드바를 두고 개별 요청 결과를 복원한다.
- 범위 밖: 대화 단위 저장 변경, 백엔드 변경, 기록 삭제·이름 변경·날짜 그룹화.

## What
- 브랜드 클릭은 추가 메뉴 없이 부채꼴 홈으로 이동한다.
- 브랜드 아래 최신순 검색 기록을 표시하고 첫 문장을 제목으로 사용한다. 전체 요청은 title로 확인한다.
- 목록의 '검색 기록' 제목과 성공 기록의 '완료' 문구는 표시하지 않는다. 접근성 레이블과 실패·미리보기 표시는 유지한다.
- 브랜드 오른쪽의 상단 세로 구분선은 표시하지 않고, 기록 목록과 본문의 세로 구분선은 유지한다.
- 선택 기록은 연한 브랜드 색상으로 강조한다. 처리 중에는 기존처럼 기록 선택을 막는다.
- 기록은 독립 스크롤을 사용하며 기존 결과 로더·오류 재시도·쿠키 기반 권한 확인을 유지한다.
- 760px 이하에서는 기록을 접고 '기록' 버튼으로 여닫는다. 바깥 영역 클릭과 Escape로 닫고 선택 후에도 닫는다.
- 중앙 UH 버튼의 기존 탐색 기능은 기록 사이드바 열기로 연결한다.
- 기록이 없으면 빈 목록 안내를 표시한다. 새 검색이나 홈 이동은 이전 답변·기록을 삭제하지 않는다.

## How
- `frontend/app/page.jsx`: 브랜드와 기존 기록 목록을 사이드바로 이동하고 별도 기록 화면·드롭다운 메뉴를 제거한다.
- `frontend/app/globals.css`: 200px / 가변 보드 / 280~400px 채팅의 3열 레이아웃과 모바일 기록 패널을 정의한다. 채팅 너비는 `clamp(280px, 28vw, 400px)`로 제한한다.
- 기존 `searchHistory`, `openHistory`, `createHistoryLoader`와 API 계약은 유지한다.
- sidebar는 현재 탭·쿠키로 복원한 요청만 표시한다. GPT와 같다는 이유로 별도 영구 저장이나 대화 모델을 만들지 않는다.

## AC
- Given 결과 화면, When 브랜드 클릭, Then 메뉴 없이 부채꼴 홈이 보이고 기록은 유지된다.
- Given 기록 2건, When 완료 기록 클릭, Then 기존 결과가 복원되고 해당 항목이 강조된다.
- Given 데스크톱, When 레이아웃 확인, Then 기록·갤러리·채팅의 스크롤 영역이 분리된다.
- Given 모바일, When 기록 버튼 클릭 및 Escape/바깥 영역 클릭/항목 선택, Then 패널을 열고 닫을 수 있고 숨겨진 목록은 탭 포커스에 포함되지 않는다.
- Given 기존 앱, When 테스트·빌드, Then 기존 기능 테스트와 빌드가 통과한다.

## 실행 계획
- 기존 메뉴의 홈 직접 이동 불가 상태 확인 → 최소 JSX/CSS 변경 → 테스트·빌드 → 실제 기록으로 홈 이동·복원·반응형 동작 검증.
- 커밋·push 없이 현재 worktree에 보존한다.

## 검증 결과
- 2026-10-02 프론트 테스트 45 passed, production build 및 `git diff --check` 통과.
- 기존 실제 검색 기록 2건으로 브랜드 클릭 후 홈 즉시 이동·기록 유지 확인.
- 완료 기록 선택 후 실제 썸네일 16개 복원 및 `aria-current="page"` 강조 확인.
- 데스크톱 사이드바 너비 약 200px, 기록 목록·갤러리·채팅의 `overflow-y: auto` 분리 확인.
- 좁은 화면의 닫힌 목록은 접근성 트리에서 제외됨을 확인했다. 기록 버튼 열기, Escape 닫기·버튼 포커스 복귀, 배경 바깥 클릭 닫기, 완료 기록 선택 후 닫기를 확인했다.
- 실제 기록 두 건만으로 검사했으므로 다량 기록의 스크롤 길이는 실측하지 않았다. 빈 목록 문구는 구현했으나 새 세션의 실제 빈 목록은 별도 검증하지 않았다.
- LLM 재호출이나 백엔드 변경 없이 검증했다. viewport를 복구하고 기존 작업과 미추적 파일을 보존했다. 커밋·push는 수행하지 않았다.
