# 세션 목록 사이드바

## Why
- 사용자는 각 입력 요청을 세션 하나의 대화로 이어서 진행한다.
- 왼쪽 목록에 요청 하나씩 나오면 세션을 구분하거나 다시 여는 데 맞지 않는다. 이전 요청과 답변은 오른쪽 대화 패널에서 스크롤해 확인할 수 있다.

## Goal
- 왼쪽 사이드바에 대화 세션 목록과 새 세션 만들기 동작을 제공한다.
- 기존 화면 배치, 색상, 간격, 반응형 동작을 유지한다. 변경 대상은 목록의 단위와 세션 선택·생성 동작이다.
- 선택된 세션의 대화 전체를 오른쪽 채팅 패널에 표시한다. 새로고침 시에는 최신 세션의 최신 Job만 복원하고 과거 대화는 요청할 때 불러온다.
- 목록은 세션 `created_at` 내림차순으로 고정한다. 가장 먼저 만든 세션은 아래에 표시하며, 세션 열기나 메시지 제출로 목록 순서를 바꾸지 않는다.
- 세션을 열어 이력을 복원하는 동안 중앙 레퍼런스 화면에 세션 로딩 상태를 표시한다.
- 범위 밖: 세션 이름 변경·삭제·검색, 화면 디자인 변경.

## What
1. 화면 진입 시 쿠키 소유자의 최근 세션 목록을 불러온다.
2. 초기 bootstrap 요청 한 번으로 세션 목록과 최신 세션의 최신 Job을 복원한다. 더 오래된 대화가 있으면 사용자가 요청할 때 불러온다. 세션이 없으면 빈 대화 상태로 시작한다.
3. 새 세션 버튼을 누르면 기존 `POST /api/sessions`를 호출하고, 빈 대화와 새 목록 항목을 선택한다.
4. 사이드바의 세션을 선택하면 그 세션의 대화 전체를 오른쪽 패널에 표시한다. 선택한 세션의 이력은 페이지별 묶음 요청으로 복원한다.
5. 새 요청은 현재 선택된 세션에 제출한다. 새로 생성한 세션도 동일하다.
6. 목록에는 bootstrap 응답의 `created_at`을 세션 식별 정보로 표시한다. 세션 제목 추출용 추가 요청은 하지 않는다.
7. 모바일의 기존 세션 목록 열기/닫기 동작을 유지한다.
8. 초기 복원은 최신 Job만 가져온다. 최신 세션의 과거 대화는 `이전 대화 불러오기` 동작으로 요청하고, 다른 세션은 선택 시 페이지별 Job 이력을 가져온다. Job마다 별도 상세 API를 호출하지 않는다.

## How
- `GET /api/sessions/bootstrap?limit=100`으로 초기 세션 목록과 최신 Job을 함께 복원한다. 세션 생성에는 기존 `POST /api/sessions`, 세션 이력에는 `GET /api/sessions/{id}/jobs`를 사용한다.
- 프론트엔드 상태는 세션 목록, 선택된 `session_id`, 선택 세션의 `turns`를 관리한다. 선택 세션이 바뀌면 이전 polling을 중단하고 해당 세션의 이력을 복원한 뒤 진행 중 job polling을 재개한다.
- 사이드바의 현재 요소와 스타일 클래스를 재사용하고 CSS·레이아웃을 변경하지 않는다. `새 세션` 버튼은 기존 사이드바 목록 항목 스타일을 사용한다.
- 세션 목록 오류와 세션 이력 복원 오류는 기존 복원 오류 UI를 사용한다. 실패 시 다른 세션으로 자동 fallback하지 않는다.
- bootstrap은 최신 Job의 Pin 미리보기만 보강한다. 세션 이력 요청은 각 페이지의 완료 Job을 묶어서 보강하며, 썸네일 URL은 저장하지 않는다.
- 세션 목록 정렬은 프론트에서 `created_at`을 기준으로 수행하며 활동 시각으로 순서를 갱신하지 않는다.

## AC (Given-When-Then)
- Given 소유자의 세션이 여러 개, When 화면을 열면, Then 세션 목록과 생성 시각 최신 세션의 최신 Job만 초기 요청으로 복원한다.
- Given 최신 세션에 과거 대화가 있음, When 첫 화면이 준비되면, Then 과거 Job은 자동 조회하지 않고 이전 대화 불러오기 동작을 제공한다.
- Given 사용자가 이전 대화 불러오기를 선택함, When 이력이 로드되면, Then 세션 이력 페이지 요청을 사용하고 Job별 상세 요청을 보내지 않는다.
- Given 세션 A가 선택됨, When 세션 B를 선택하면, Then 오른쪽 패널이 B의 전체 대화로 바뀌고 A의 대화를 목록에 turn별로 표시하지 않는다.
- Given 새 세션 버튼, When 누르면, Then 세션 생성 API를 호출하고 새 빈 세션을 선택한다.
- Given 세션 B가 선택됨, When 메시지를 제출하면, Then 요청 본문에 B의 `session_id`를 전달한다.
- Given 생성 시각이 다른 세션이 여러 개, When 세션을 열거나 메시지를 제출하면, Then 목록 순서는 생성 시각 내림차순으로 유지되고 가장 먼저 만든 세션이 아래에 표시된다.
- Given 세션 A에서 세션 B를 선택, When B의 대화 이력을 불러오는 동안, Then 중앙 레퍼런스 화면에 로딩 상태를 표시하고 홈 콘텐츠를 표시하지 않는다.
- Given 진행 중 job이 있는 세션을 전환, When 이전 polling이 응답하면, Then 이전 세션 결과가 새 세션의 대화에 섞이지 않는다.
- Given Pin이 포함된 완료 Job이 여러 개인 세션, When 과거 세션을 열면, Then 세션 이력 페이지 요청에서 완료 Job들을 묶어 재조회해 응답 전용 썸네일과 접근 상태를 표시한다.
- Given 기존 데스크톱/모바일 화면, When 세션 사이드바를 사용하면, Then 기존 디자인과 레이아웃·모바일 열기/닫기 동작을 유지한다.
- Given 세션이 하나도 없음, When 화면을 열면, Then 빈 대화 상태와 새 세션 생성 동작을 제공한다.
