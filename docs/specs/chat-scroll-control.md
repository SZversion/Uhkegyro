# 채팅 스크롤 제어

## Why

- **페르소나**: 결과 생성 중 이전 요청과 답변을 확인하는 사용자
- **상황**: 새 요청을 보낸 뒤 처리 상태를 기다리면서 대화 위쪽 내용을 읽는다.
- **문제**: 진행 상태가 갱신될 때마다 대화창이 아래로 이동해 사용자의 스크롤 위치를 유지할 수 없다.
- **측정 지표**: 요청 처리 중 polling 업데이트가 사용자의 스크롤 위치를 변경하는 횟수 0회.

## Goal

- 요청을 보낸 직후 새 요청이 보이도록 대화창을 맨 아래로 한 번 이동한다.
- 요청 처리 중 상태 갱신으로 자동 스크롤하지 않는다.
- 요청 외 화면 갱신에서도 사용자가 보고 있는 위치를 유지한다.
- Out of Scope: 자동 스크롤 버튼, 사용자의 직접 스크롤 입력 제한, 결과판 스크롤 변경.

## What

- 새 요청이 접수되고 대화 turn이 추가되면 하단으로 한 번 이동한다.
- 완료·실패를 포함한 진행 상태 polling은 대화 내용을 갱신하지만 스크롤 위치는 바꾸지 않는다.
- 세션 복원은 현재 동작처럼 마지막 대화를 보이도록 하단으로 한 번 이동한다.
- 이전 대화 불러오기는 현재 스크롤 위치를 유지한다.

## How

- `panel-top`의 `scrollTop`을 변경하는 자동 스크롤은 명시적인 요청 제출 및 세션 복원 직후에만 실행한다.
- 제출 후 turn ID와 복원 완료 신호를 ref로 보관하고, 해당 상태 변경이 DOM에 반영된 뒤 한 번 소비한다.
- `turns`, `termGuide`, `mobilePanel`의 일반 변경을 자동 스크롤 트리거로 사용하지 않는다.
- 기존 `panel-top` 요소와 UI 구조를 유지하며 백엔드는 변경하지 않는다.

## AC (Given-When-Then)

- **AC-01 · 새 요청 하단 이동**
  - Given 대화창이 위쪽 위치에 있음
  - When 요청이 접수되어 새 turn이 표시됨
  - Then 대화창은 맨 아래로 한 번 이동한다.
- **AC-02 · 처리 중 위치 보존**
  - Given 요청 처리 중 사용자가 대화창을 위로 스크롤함
  - When polling 상태나 답변 turn이 갱신됨
  - Then 대화창은 사용자가 보고 있는 위치를 유지한다.
- **AC-03 · 세션 복원**
  - Given 세션 대화가 복원됨
  - When 마지막 turn이 표시됨
  - Then 대화창은 맨 아래로 한 번 이동한다.
- **AC-04 · 이전 대화 로드**
  - Given 사용자가 현재 대화 위치에 있음
  - When 이전 대화가 추가로 로드됨
  - Then 자동으로 맨 아래로 이동하지 않는다.
