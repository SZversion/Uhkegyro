# 대화 복원 실패 후 새 요청 복구

## Why

- **페르소나**: 로컬 또는 운영 프론트엔드에서 대화를 시작하는 사용자.
- **상황**: 페이지 진입 시 기존 세션 목록이나 이력을 불러온다.
- **문제**: 복원 요청이 실패하면 오류 안내는 보이지만 입력창이 계속 비활성화되어 새 대화를 시작할 수 없다.
- **측정 지표**: 복원 요청 실패 후 새 요청 제출이 가능하고, 새 세션 생성 경로로 진행된다.

## Goal

- 초기 대화 복원이 실패해도 입력창을 활성화한다.
- 복원 오류 안내는 유지하고, 사용자가 다음 요청을 제출하면 새 세션을 생성한다.

**Out of Scope**: 기존 세션 데이터 삭제·이전, 자동 재시도, DB 연결값 변경, 복원 API 계약 변경.

## What

### Happy Path

1. 페이지가 대화 목록과 최근 세션을 불러온다.
2. 복원에 실패하면 오류 안내를 표시하고 입력창을 활성화한다.
3. 사용자가 새 요청을 제출하면 기존 동작대로 새 세션을 만들고 Agent 요청을 보낸다.

### Edge Cases

| 상황 | 처리 방식 |
| --- | --- |
| 세션 쿠키가 없어 복원이 `401`로 끝남 | 빈 대화로 초기화하고 입력을 활성화한다. |
| 세션 목록 또는 이력 API가 실패함 | 복원 오류를 표시하되 입력을 활성화한다. |
| 새 세션 생성도 실패함 | 요청 오류를 표시하고 재시도할 수 있도록 입력을 유지한다. |

## How

- 범위는 초기 프론트엔드 복원 처리와 해당 동작의 테스트로 한정한다.
- 복원 실패 상태는 `conversationReady=true`, `sessionId=null`, 빈 대화 기록으로 전환한다.
- 기존 `createConversation` 호출 경로가 `sessionId=null`일 때 새 세션을 만든다.
- 세션 복원 API, 쿠키, DB 스키마는 변경하지 않는다.

## AC (Given-When-Then)

**AC-01 · 미인증 사용자의 빈 대화 시작**
- GIVEN: 세션 쿠키가 없어 목록·복원 API가 `401`을 반환한다.
- WHEN: 프론트엔드가 초기 복원을 수행한다.
- THEN: 빈 대화 상태로 입력창이 활성화된다.

**AC-02 · 복원 API 장애 후 새 대화**
- GIVEN: 목록 또는 이력 복원이 실패한다.
- WHEN: 프론트엔드가 오류 상태로 복구한다.
- THEN: 오류 안내를 유지하면서 입력을 허용하고, 제출 시 새 세션 생성 경로를 사용한다.
