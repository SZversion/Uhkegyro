# 독립 역할 검색 병렬 실행

## Why

- 페르소나·상황: 체형·포즈·시점 레퍼런스를 함께 요청하는 사용자.
- 문제: LLM이 한 응답에 여러 검색을 선택해도 worker가 순차 실행해 대기가 누적된다.
- 지표: 동시 검색 수, 역할별 결과 보존, 동일 지연 대역의 순차/병렬 검색 시간.

## Goal

- 동일 LLM 응답의 독립 역할 검색을 병렬 실행한다.
- 같은 AgentJobWorker의 모든 Job은 검색 작업 최대 3개 한도를 공유한다.
- 기존 역할별 최대 3회 재시도, 1초·2초 backoff, 오류 계약을 유지한다.
- 범위 밖: 모델 추가, 썸네일 중복 조회 제거, UI/API 변경, 배포, 검색 엔진 정책 변경.

## What

1. LLM에 미완료 승인 역할의 검색을 한 응답에서 함께 선택하도록 안내한다.
2. `search_pinterest_pins` 호출만 검증하고 병렬 실행한다. 등록된 다른 도구는 tool selection에 노출하거나 실행하지 않는다.
3. MCP 검색과 해당 결과의 Widget 조회가 끝나면 공유 실행 자리를 반환한다.
4. 최초 선택 이후 선택에서 빠진 승인 역할 및 unavailable 역할은 worker 코드가 검색한다. 정상 빈 결과는 완료로 취급한다.
5. 동일 응답의 동일 역할은 첫 유효 호출만 실행한다. 잘못된 조각은 역할을 예약하지 않는다.
6. 빈 결과는 재시도하지 않는다. unavailable은 worker 코드가 재시도하며 대기 중 실행 자리를 점유하지 않는다. 역할별 최대 3회와 1초·2초 backoff를 유지한다.
7. 설정 오류·취소는 병렬 작업을 취소하고 종료까지 기다린다. 한 역할의 검색 장애는 다른 역할의 결과를 유지한다.

## How

- 변경: backend/services/agent_worker.py와 검색 worker 테스트. 기존 worker Spec도 갱신한다.
- AgentJobWorker 인스턴스에 asyncio.Semaphore(3)를 둔다. 프로세스/인스턴스 간 전역 제한은 아니다.
- asyncio.gather로 검색 묶음을 실행하고 finally에서 미완료 task 취소·회수를 보장한다.
- 승인 role과 query_fragments의 정확한 일치, LLM이 선택한 도구 호출 한도를 유지한다. 코드 재시도는 역할별 최대 3회로 별도 제한한다.
- 동일 응답의 역할 예약은 외부 호출 전에 수행한다. 잘못된 인자·중복은 도구 오류이며 검색 시도에 포함하지 않는다.
- Pinterest 검색 외 도구는 실행하지 않는다. 일반 요청과 결과 스키마, 썸네일 비저장 정책은 유지한다.
- LLM이 한 번에 일부 역할만 선택해도 처리한다. 첫 선택 응답의 모든 도구·병렬 검색·Widget 처리 후 미검색 역할은 worker가 검색하고, unavailable은 코드로 재시도한다. 상세 호출 순서는 [검색 도구 선택 및 코드 재시도 Spec](./search-tool-selection-rounds.md)을 따른다.
- 성능 비교는 같은 대역의 순차 합산 시간과 병렬 검색 단계 시간을 비교하며 실제 서비스 지연으로 주장하지 않는다.
- 2026-10-06 검증: 병렬 검색·worker·LLM 도구 호출·MCP gateway·Widget·assembler·Job 재시도 테스트 59건 통과. DB 통합 테스트 1건은 연결 설정 없이 skip. 지연 대역 비교는 순차 0.149초 / 병렬 0.063초이며 실제 외부 서비스 지연은 미측정이다.

## AC

- AC-01: Given 독립 역할 3개, When 한 응답에서 검색 선택, Then 검색이 겹쳐 실행되고 순차 대역보다 빠르며 결과·tool_call_id 순서는 보존된다.
- AC-02: Given 같은 worker에서 복수 Job 검색, When MCP와 Widget이 대기, Then 합산 실행 수는 최대 3개이며 Widget 완료 전 자리를 반환하지 않는다.
- AC-03: Given 잘못된 검색어·중복 역할, When 호출 묶음 실행, Then 첫 유효 호출만 MCP에 전달되고 오류 호출은 검색 시도로 집계하지 않는다.
- AC-04: Given 성공·빈 결과·unavailable 혼합, When 재시도, Then 성공·빈 결과는 유지하고 장애 역할만 최대 3회 및 1초·2초 대기로 재시도한다. 대기 중 다른 Job은 검색할 수 있다.
- AC-05: Given 설정 오류 또는 작업 취소, When 검색 묶음 중단, Then 남은 작업이 종료되고 설정 오류 계약이 보존되며 실행 자리가 회수된다.
- AC-06: Given MCP 목록에 Pinterest 검색 외 도구가 존재, When tool selection 및 실행, Then 그 도구는 LLM에 제공되지 않고 호출되지 않는다.
- AC-07: Given LLM이 역할을 하나씩 선택하거나 검색이 불필요, When 처리, Then 기존 처리와 실패 분류가 유지된다.
